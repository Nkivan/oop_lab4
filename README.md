# Лабораторна робота 4 - варіант 2

Тема: створення та використання делегатів, подій і лямбда-виразів.

## Опис проєкту

Консольний застосунок демонструє роботу делегатів і подій у C# на прикладі завдань варіанта 2.

У першій частині рядок і символ передаються у власний делегат `CharCountOperation`, який повертає, скільки разів символ використано в рядку. Одна й та сама операція викликається через делегат двома способами: за допомогою анонімного методу та лямбда-виразу.

У другій частині моделюється калькулятор із математичними операціями над накопиченим значенням (додавання, віднімання, множення, цілочисельне ділення). Коли виконується цілочисельне ділення, калькулятор генерує подію `IntegerDivision`, а окремі класи-обробники реагують на неї: один виводить повідомлення користувачеві, інший веде статистику.

## Структура

- `Program.cs` - точка входу, запускає меню.
- `ConsoleMenu.cs` - меню: автоматичні демонстрації та інтерактивне введення.
- `CharCountOperation.cs` - оголошення делегата для підрахунку символу.
- `DelegateDemo.cs` - анонімний метод, лямбда-вираз і їх виклик через делегат.
- `Calculator.cs` - компонент із подією `IntegerDivision` і методом `OnIntegerDivision`, що її генерує.
- `IntegerDivisionEventArgs.cs` - аргументи події.
- `DivisionConsoleHandler.cs` - обробник події: повідомлення користувачеві.
- `DivisionStatisticsHandler.cs` - обробник події: облік ділень.
- `CalculatorDemo.cs` - демонстрація підписки, відписки, мультиадресності.
- `SCHEMES.md` - схеми роботи та взаємодії класів.

## Виконані вимоги

**Завдання 1 (варіант 2: пошук у рядку кількості використань заданого символу)**

- Кількість входжень символу в рядок обчислюється через делегат `CharCountOperation`.
- Логіку обчислення записано безпосередньо в анонімному методі (цикл `for`) та в лямбда-виразі (метод `Count` із LINQ).
- Реалізовано і анонімний метод, і лямбда-вираз (оцінка «добре»).
- Додатково показано, чим є делегат всередині (`MulticastDelegate`) і побічний ефект замикання, коли лямбда захоплює зовнішню змінну.

**Завдання 2-3 (варіант 2: клас «математичні операції», подія «цілочисельне ділення»)**

- Створено компонент багаторазового використання `Calculator` із подією `IntegerDivision`.
- Для події створено клас аргументів `IntegerDivisionEventArgs` (ділене, дільник, частка, остача).
- Для опису події використано стандартний узагальнений делегат `EventHandler<IntegerDivisionEventArgs>`.
- Застосунок визначає методи-обробники, які отримують ініціатора події (`sender`) та аргумент події.

**Для оцінки «відмінно»**

1. Клас-аргумент події: `IntegerDivisionEventArgs`.
2. Клас, у якому генерується подія (там і сама подія, і метод, що її викликає): `Calculator` (`IntegerDivision` та `OnIntegerDivision`).
3. Класи, у яких є методи-обробники події: `DivisionConsoleHandler` і `DivisionStatisticsHandler`.
4. Методи-обробники мають стандартний підпис подій .NET: `void HandleIntegerDivision(object sender, IntegerDivisionEventArgs e)`.

**Як трактується подія.** Подія «цілочисельне ділення» генерується після кожного виконаного цілочисельного ділення, а аргумент події містить ділене, дільник, частку й остачу. Ділення на нуль і переповнення розрядної сітки повідомляються винятками (`DivideByZeroException`, `OverflowException`), а не подією.

## Запуск

З кореня проєкту:

```
dotnet run --project Lab4.csproj
```

Або відкрити `Lab4.sln` у Visual Studio і запустити (F5).

Меню:

| Пункт | Дія |
|---|---|
| 1 | Демонстрація: делегат, анонімний метод, лямбда-вираз |
| 2 | Демонстрація: калькулятор і подія цілочисельного ділення |
| 3 | Підрахунок символу в рядку (введення з клавіатури) |
| 4 | Калькулятор: інтерактивні операції, підписка й відписка від події |
| 0 | Вихід |

Очікуваний результат пункту 1: для рядка `banana` і символу `a` обидва способи повертають 3. Очікуваний результат пункту 2: перше ділення `100 / 7 = 14, остача 2` виводить повідомлення та враховується в статистиці; після відписки консольного обробника (`-=`) наступне ділення повідомлення не виводить, але статистика продовжує вестися.

## Контрольні запитання

1. **Сутність делегата.** Делегат - типобезпечне посилання на один або кілька методів із певною сигнатурою. Він дозволяє передавати методи як параметри, зберігати їх у змінних і викликати пізніше; на ньому побудовані зворотні виклики та події.
2. **Приклад опису та виклику.** `public delegate int CharCountOperation(string text, char symbol);`, далі `CharCountOperation operation = (text, symbol) => text.Count(c => c == symbol);` і виклик `int count = operation("banana", 'a');`.
3. **Склад класу делегата.** Делегат - клас, похідний від `System.MulticastDelegate` (а той від `System.Delegate`). Для оголошення делегата компілятор створює запечатаний клас із конструктором і методом `Invoke` із потрібною сигнатурою (методи `BeginInvoke` та `EndInvoke` у сучасному .NET не підтримуються).
4. **Контроль типів.** Компілятор перевіряє, що кількість і типи параметрів та тип результату методу збігаються із сигнатурою делегата (з урахуванням коваріантності повернення та контраваріантності параметрів). Метод із невідповідним підписом не можна присвоїти делегату: буде помилка компіляції.
5. **У що розгортається делегат.** У екземпляр класу, похідного від `MulticastDelegate`. Він зберігає цільовий об'єкт (`Target`, для статичних методів `null`), посилання на метод (`Method`) і список викликів (`GetInvocationList`) для мультиадресних делегатів.
6. **Анонімний метод.** Метод без імені, який записують у місці використання за допомогою ключового слова `delegate` і присвоюють змінній делегата, наприклад `delegate (string text, char symbol) { ... }`. Може використовувати змінні зовнішнього методу.
7. **Лямбда-вираз.** Короткий запис анонімної функції у вигляді `(параметри) => вираз` або `(параметри) => { оператори }`, типи параметрів виводяться з делегата. Приклади: `x => x * 2`, `(a, b) => a + b`, `(text, symbol) => text.Count(c => c == symbol)`.
8. **Побічні ефекти.** Анонімні методи та лямбди захоплюють зовнішні змінні як змінні, а не як значення (замикання). Тому якщо змінну змінити після створення лямбди, зміниться й результат (у програмі це показано змінною `target`). Результат залежить від зовнішнього стану та моменту виклику, захоплена змінна живе, поки живе делегат, а в циклах `for` усі лямбди можуть ділити одну змінну лічильника.
9. **Приклад події.** `public event EventHandler<IntegerDivisionEventArgs> IntegerDivision;`
10. **Генерація події.** Клас-власник викликає делегат події, зазвичай у захищеному віртуальному методі (у роботі це `OnIntegerDivision`): `IntegerDivision?.Invoke(this, e);`. Оператор `?.` захищає від випадку, коли підписників немає. Генерувати подію може лише клас, у якому її оголошено.
11. **Підписка та скасування підписки.** Оператор `+=` додає метод-обробник до події, а `-=` видаляє його: `calculator.IntegerDivision += handler.HandleIntegerDivision;`. Поза класом-власником із подією можна виконувати лише ці дві операції. Відписуватися варто, щоб подія не утримувала об'єкт-обробник у пам'яті.
12. **Мультиадресні делегати.** Містять список викликів. Методи додаються операторами `+`, `+=`, видаляються `-`, `-=`, і викликаються по черзі в порядку додавання. Якщо делегат повертає значення, результатом буде значення останнього методу. Виняток у одному обробнику перериває виклик решти. Делегати незмінні: кожна операція створює новий делегат.
13. **Різниця між делегатом і подією.** Делегат - тип, змінну якого можна викликати з будь-якого місця, перепризначити чи очистити. Подія - обгортка над делегатом із обмеженим доступом: зовні можна лише підписатися й відписатися (`+=`, `-=`), а викликати подію може тільки клас, у якому її оголошено.
